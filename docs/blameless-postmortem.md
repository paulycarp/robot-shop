# Incident Postmortem: Payment Service Availability Degradation Drill
**Incident Reference**: INC-2026-10-01  
**Severity Level**: SEV-1 (Critical)  
**Date**: October 16, 2026  
**Incident Commander / Author**: paulycarp (DevOps On-Call)  
**Status**: Resolved & Closed  

---

## 1. Executive Summary
On October 16, 2026, during an unannounced operational incident drill, the **Stan's Robot Shop Payment Service** experienced a 100% loss of availability. Synthesized user traffic generated by `load-gen` began failing at checkout, breaching the 99.5% availability Service Level Objective (SLO). 

The automated monitoring pipeline detected the failure within 60 seconds, triggering a critical alert in the team's `#devops-alerts` Slack channel with a direct link to the operational runbook. Following the runbook triage steps, the on-call engineer identified the simulated fault, executed immediate mitigation within 4 minutes, verified system recovery via Grafana Golden Signals, and restored full checkout availability with zero permanent data loss.

## 4. Root Cause Analysis (5 Whys)
1. **Why did checkout fail?** The payment service container was rejecting incoming checkout requests.
2. **Why was it rejecting requests?** The pod crashed upon attempting to bind to an unreachable upstream gateway.
3. **Why was the gateway unreachable?** The deployment environment variable had been altered to a malformed address during the drill.
4. **Why was this change accepted?** The deployment lacked an automated pre-deployment schema validation check.
5. **Why was there no automated check?** Upstream configuration validation was previously handled manually.

---

## 5. What Went Well vs. Where We Got Lucky vs. Where We Need Improvement

### What Went Well:
* Automated SLO alerting in Prometheus and Alertmanager fired within 60 seconds of the drop.
* The runbook link provided directly in the Slack alert allowed the engineer to diagnose the issue without searching documentation repos.
* The local multi-node Kind cluster and Helm deployment allowed rapid rolling recovery.

### Where We Got Lucky:
* The fault was isolated to the `payment` service; the `catalogue` and `cart` services continued serving traffic without cascading failures.

### Where We Need Improvement:
* Pod readiness probes took 20 seconds to report unhealthy status; tuning probe failure thresholds could accelerate automatic endpoint eviction.
