## 📌 Project Overview
Capstone 2 focuses on **observability, site reliability engineering (SRE), and incident response** on a modern microservices e-commerce application, **Stan's Robot Shop**.

### Core Architecture & Key Services
Stan's Robot Shop consists of multiple interconnected microservices running on Kubernetes:
* **`web`**: Nginx frontend serving the single-page application (accessible at `http://localhost:8080`).
* **`catalogue`**: Node.js microservice querying the MongoDB catalogue database.
* **`cart`**: Node.js microservice managing active user shopping carts in Redis.
* **`payment`**: Python Flask microservice processing checkout requests and transactions.
* **Databases & Queues**: MongoDB, Redis, MySQL, RabbitMQ.
* **`load-gen`**: Synthetic client traffic generator executing automated user browsing, cart updates, and purchases.

## 🛠️ The 6 Implementation Steps

### Step 1: Deploy and Watch
Deployed to the Kubernetes cluster using the configured Helm chart with Instana agent hooks decoupled:
```bash
kubectl create namespace robot-shop
helm install robot-shop K8s/helm --namespace robot-shop
```
* **Web UI**: [http://localhost:8080](http://localhost:8080)
* Continuous synthetic traffic is generated by the `load-gen` deployment.

---

### Step 2: See the Metrics (Prometheus & Grafana)
Installed the monitoring stack via Helm:
```bash
helm install prometheus prometheus-community/kube-prometheus-stack --namespace monitoring -f monitoring/values-prometheus.yaml
```
* **Grafana**: [http://localhost:3000](http://localhost:3000) (`admin` / `admin`)
* **Prometheus**: [http://localhost:9090](http://localhost:9090)
* **Dashboard as Code**: The [Golden Signals Dashboard](monitoring/dashboards/robot-shop-golden-signals.json) tracks:
  * **Throughput / Request Rate (RPS)** across services
  * **Error Rate (%)** tracking 5xx responses
  * **Latency** (p95 request duration)
  * **CPU & Memory Working Set** consumption

---

### Step 3: Collect the Logs (Fluent Bit & Loki)
Centralized container log aggregation using Fluent Bit and Grafana Loki:
```bash
kubectl apply -f monitoring/logging/loki-deployment.yaml
kubectl apply -f monitoring/logging/fluent-bit.yaml
kubectl apply -f monitoring/logging/loki-datasource-configmap.yaml
```
* Container logs are parsed with Kubernetes metadata and shipped to Loki at `http://loki.monitoring.svc.cluster.local:3100`.
* In Grafana Explore, logs can be queried by service and severity:
  ```logql
  {namespace="robot-shop", container="payment"} |= "error"
  ```

---

### Step 4: Follow One Trace (OpenTelemetry & Jaeger)
Distributed tracing pipeline deployed in the `monitoring` namespace:
```bash
kubectl apply -f monitoring/tracing/jaeger-deployment.yaml
kubectl apply -f monitoring/tracing/otel-collector.yaml
```
* **Jaeger UI**: View request execution paths across microservices.
* **OpenTelemetry Collector**: Accepts OTLP gRPC (`4317`) and HTTP (`4318`) traces and exports to Jaeger.

---

### Step 5: Set One SLO & Error Budget
* **SLO Target**: 99.0% availability for core services (99.5% for Payment).
* **Policy Document**: Full 1-page agreement documented in [`docs/slo-error-budget-policy.md`](docs/slo-error-budget-policy.md).
* **Alerting**: Defined in [`monitoring/slo/prometheus-slo-rules.yaml`](monitoring/slo/prometheus-slo-rules.yaml). When an SLO breach occurs, Alertmanager alerts the `#devops-alerts` Slack channel and includes a direct link to the operational [Runbook](docs/runbook.md).

---

### Step 6: Incident Drill & Blameless Postmortem
During the incident drill, a fault was injected into the payment service.
1. **Mitigation First**: Identified and rolled back deployment via runbook steps.
2. **Root Cause Analysis**: Diagnosed using logs in Loki and traces in Jaeger.
3. **Blameless Postmortem**: Complete report with timeline, 5 Whys, and preventative actions documented in [`docs/blameless-postmortem.md`](docs/blameless-postmortem.md).
